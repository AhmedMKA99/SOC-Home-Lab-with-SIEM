# 04, Linux Endpoint

This document records the build of the monitored Linux endpoint: the Ubuntu VM, the Wazuh agent enrollment, and the auditd configuration that provides command-execution telemetry (the Linux equivalent of Sysmon on Windows).

---

## The VM

An Ubuntu Desktop 26.04 LTS installation was performed manually from the official ISO (unlike Wazuh and Windows, which were imported as pre-built appliances).

| Property | Value |
|----------|-------|
| ISO | ubuntu-26.04-desktop-amd64.iso |
| OS | Ubuntu 26.04 LTS Desktop |
| Base Memory | 4096 MB |
| CPU | 2 vCPUs |
| Disk | 30 GB, dynamically allocated |
| Network | NAT Network, SOC-Lab |
| IP address | 10.0.10.5 |

Due to the 16 GB host RAM constraint, the Linux endpoint is run with the Windows endpoint shut down. Both endpoints can run together for lighter tasks, but heavy workloads are handled one at a time.

---

## Wazuh Agent

The Wazuh Linux agent was installed using the command generated by the dashboard's Deploy new agent wizard.

| Parameter | Value |
|-----------|-------|
| Manager address | 10.0.10.3 |
| Agent name | Linux-Endpoint |
| Agent group | default |
| Package | DEB, amd64 |

Installation steps:

1. The dashboard wizard generated a tailored `wget` and `dpkg -i` command.
2. The command was executed on the endpoint with `sudo`.
3. The agent service was enabled and started:

```
sudo systemctl daemon-reload
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent
```

**Result:** the agent appeared as Active on the Wazuh dashboard, assigned agent.id 002.

## auditd for Command-Execution Telemetry

The Wazuh Linux agent by default reads system logs from `/var/log/syslog`, `/var/log/auth.log`, and, if present, `/var/log/audit/audit.log`. Default Ubuntu installations do not include the Linux Audit framework, so it must be installed and configured to give the Wazuh agent detection-grade visibility into command execution. This is the Linux equivalent of what Sysmon provides on Windows.

### Installation

```
sudo apt update && sudo apt install auditd audispd-plugins -y
```

### Command Monitoring Rules

Audit rules were added to track every use of the `execve` system call, which is invoked whenever any command is run on the system:

```
sudo tee /etc/audit/rules.d/wazuh.rules > /dev/null <<'EOF'
-a exit,always -F arch=b64 -S execve -k audit-wazuh-c
-a exit,always -F arch=b32 -S execve -k audit-wazuh-c
EOF
```

The `-k audit-wazuh-c` key is a label that lets Wazuh (and later analysts) identify command-execution events specifically.

### Loading and Verification

```
sudo augenrules --load
sudo auditctl -l
```

`auditctl -l` prints back the currently loaded rules, confirming both the 64-bit and 32-bit `execve` rules are active.

### Wazuh Agent Restart

```
sudo systemctl restart wazuh-agent
```

Once restarted, the agent begins forwarding `audit.log` entries to the Wazuh manager alongside the default log sources.

### Service Health Checks

Health of both daemons was verified with:

```
sudo systemctl status wazuh-agent
sudo systemctl status auditd
```

Both showed `active (running)` after the changes.

## Verification

The Linux endpoint's telemetry was validated with a controlled test in M5 Simulation 2:

- Created a new local user: `sudo useradd -m testuser`
- Set a password: `echo "testuser:P@ssw0rd123!" | sudo chpasswd`
- Added to the `sudo` group: `sudo usermod -aG sudo testuser`

Within 60 seconds, the Wazuh dashboard produced the following alerts for the Linux-Endpoint agent:

- **Rule 5901** New group added to the system (Level 8)
- **Rule 5902** New user added to the system (Level 8)
- **Rule 5402** Successful sudo to ROOT executed (Level 3)
- **Rule 5501/5502** PAM: Login session opened/closed (Level 3)

Combined with M5 Simulation 3 (failed sudo attempts), which produced:

- **Rule 5557** unix_chkpwd: Password check failed (Level 5)
- **Rule 5503** PAM: User login failed (Level 5)

The Linux endpoint is fully monitored: Wazuh agent active, auditd providing command-execution telemetry, and detection rules matching expected activity.

Milestone **M4 (both endpoints with detection-grade telemetry)** is complete.
